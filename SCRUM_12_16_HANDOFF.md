## What changed

- SCRUM-12: existing accessible status indicator reused in a connection panel. The monitor is polled with a timeout and no overlapping requests. A failed monitor is red; other services become grey/unknown instead of retaining green. Each service has a text label as well as a colour. Mock results are explicitly simulated. The monitor's service flags mean a process is listening on the VM's service port; they are not proof that all service/database operations succeed.
- SCRUM-16: save current settings, list presets, and load a selected preset into the form for CPU, memory, latency or packet loss. Loading never starts an injection. Frontend and backend reject out-of-range and non-integer values. Live presets use MongoDB through the Metrics API; Mock presets use separate browser storage. Failures are visible and do not claim success.
- The preset schema follows Mayank's SCRUM-15 proposal. Added the missing API routes without importing unrelated work from that branch. Shared parameter validation is extracted unchanged from Tarun's orchestrator.
- Tarun's same-origin gateway and per-VM dashboard architecture are preserved. No multi-VM launcher work (SCRUM-18) is claimed here.
